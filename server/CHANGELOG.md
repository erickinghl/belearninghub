## 2026-06-13 ｜ 学习时长统计（心跳上报）

**做了什么**
- 用户看课程时，前端每60秒发一次"还在学"的心跳，后端累加学习时长。
- 后台会员详情显示：累计学习、今日学习、各课程学习时长分布。
- 总览加"学习时长(时)"。

**改了哪些文件**
| 文件 | 改动 |
|------|------|
| `app/model/study_log.js` | 新增：学习时长表模型 |
| `app/controller/study.js` | 新增：心跳接口 `/mobile/study/heartbeat` |
| `app/controller/member.js` | detail 加学习时长统计 + 各课程分布；overview 加总学时 |
| `app/router.js` + `config/config.default.js` | 注册 study 路由 + auth.match |
| `api/api.js`（前端） | 加 studyHeartbeat 接口 |
| `pages/course/course.vue`（前端） | 课程页挂心跳定时器（进页开始/离开停止/页面隐藏暂停） |
| `database/migrations/2026-06-13_study_log.sql` | 建 study_log 表 |

**大白话讲解**
- 学习时长后端算不出来，必须前端"埋点"上报。我们用**心跳**：在课程页每60秒发一次信号，后端往"今天这门课"的记录加60秒。
- 表设计巧思：用 `(用户+课程+日期)` 唯一键，每人每天每门课只存一行（心跳来了就累加），而不是每60秒存一行——否则一天就几百行，数据爆炸。**聚合存储，不要流水存储。**
- 防作弊：单次心跳最多累加120秒（前端就算改成发"我学了1万秒"也被后端卡住）。**永远不要相信前端传的数字，后端要兜底校验。**
- 暂停逻辑：页面切到后台/最小化时（document.hidden）不上报——人没在看就不算时长，数据才准。

## 2026-06-13 ｜ 会员详情加入 留言/点赞/纠错 互动记录

**做了什么**
- 后台会员详情里，新增展示这个会员的：留言记录（在哪道题留了什么言）、点赞记录（点赞了哪些题）、纠错记录（纠了什么、状态、回复）。
- 顶部统计卡也加了"留言/点赞/纠错"三个数字。

**改了哪些文件**
| 文件 | 改动 |
|------|------|
| `app/controller/member.js` | detail 接口查 question_comment / question_like / question_correction，并关联题目标题 |
| `app/public/admin.html` | 详情弹窗加 3 块表格（留言/点赞/纠错）；统计卡加 3 个数字 |

**大白话讲解**
- 这次**没建新表、没写 SQL**——因为这些数据"题目功能条"和"纠错功能"早就在采集了，只是之前没在会员详情里查出来展示。这说明：**好的数据采集是一次性的，后面要什么报表都能从已有数据里拼出来。**
- 关键细节：光显示 `question_id`（题目编号）GM 看不懂，所以一次性把涉及的题目标题查出来做成"编号→标题"对照表（map），每条记录贴上题目名。这叫**用一次查询解决 N 条记录的关联**，避免在循环里逐条查数据库（那样慢）。

## 2026-06-13 ｜ 视频上传大小限制 + 默认头像内置款式

**做了什么**
- 后台能填一个数字（如 50MB）限制视频上传大小，超过就拒绝。
- 默认头像加了 4 个内置款式可点选，也能上传自己的图。

**改了哪些文件**
| 文件 | 改动 |
|------|------|
| `app/controller/file.js` | 视频上传按 `sys_setting.video_max_mb` 限制大小；图片继续自动压缩 |
| `config/config.default.js` | multipart 硬上限放宽到 500mb（真正限制交给后台可配项） |
| `app/public/avatars/avatar-1~4.png` | 新增 4 个内置默认头像 |
| `app/public/admin.html` | 默认头像区加内置款式选择；新增"视频上传限制"卡片 |
| `database/migrations/2026-06-13_video_limit.sql` | 插入 `video_max_mb` 配置键 |

**大白话讲解**
- 图片能用 sharp 自动压小，但视频压缩要 ffmpeg（重、慢），所以视频改成"超过设定大小就拒收"，管理员可随时调这个数字。
- 注意坑：egg 框架自己有个 50MB 上传硬限制会"半路掐断"，所以把它放宽到 500MB，让真正的限制交给后台那个可配的数字。
- 设计原则：**凡是运营会想调的数字/开关，做成后台可配，别写死在代码里。**

**做了什么**（这次跨度大，合并记录）

- 默认头像可后台配置，未上传头像不再空白。
- 全站 PC 宽屏适配（顶部导航栏 + 内容居中）。
- 题目智能导入（粘贴文本识别）+ 组合题（阅读理解/完型/共用选项/选词填空）。
- 登录/注册页、答题卡页、专栏页美化；我的页改页内 tab 切换。

**改了哪些文件（主要）**
| 文件 | 改动 |
|------|------|
| `app/controller/file.js` | 接入 sharp 图片压缩 |
| `app/controller/setting.js` + `app/model/sys_setting.js` | 全局配置（默认头像） |
| `app/controller/question.js` | 智能导入解析器 + 组合题解析 |
| `app/controller/practice.js` | 组合题答题判分 |
| 前端 `pages/*` 多个页面 + `components/pc-header/` | PC 适配、美化 |

**大白话讲解**
- 图片为什么慢：原图 8~12MB 没压过，局域网传当然慢；sharp 把它缩到 1280 宽、质量 80，小几十倍。
- PC 为什么之前是窄条：uni-app 默认给 H5 套了 `max-width:480px`，解除它 PC 才能铺开。
- 组合题怎么存：一个大题（材料+多个小题）整组存一行，子题放在 JSON 字段里，不动现有扁平题。

## 使用说明：怎么把数据库迁移应用到新环境

部署到新服务器时，按时间顺序执行 `database/migrations/` 下的 SQL 文件即可建表。
或直接导入完整备份 `database/egg-edu-full.sql`（含结构+数据，一步到位）。
